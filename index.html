1. Introducción

En esta práctica se desarrolló una aplicación web para registrar triángulos a partir de tres puntos. Se comenzó con las clases Punto y Triangulo del profesor y se completó el cálculo de los lados y la clasificación. Después se conectó la aplicación con PostgreSQL en Neon para guardar las coordenadas y los resultados.

El trabajo permitió relacionar la programación orientada a objetos con un formulario web y una base de datos en la nube. Las capturas muestran los avances iniciales, las advertencias de compilación y los resultados obtenidos al registrar tres tipos de triángulo.

El reporte sigue la lista de cotejo del profesor: portada, índice, introducción, marco teórico con citas APA, procedimiento detallado, conclusión y referencias. La ortografía y la justificación se cuidan en el contenido; la paginación se aplica al imprimir.

Objetivo

Desarrollar una aplicación sencilla con ASP.NET Core que reciba las coordenadas de tres puntos, utilice las clases Punto y Triangulo para calcular y clasificar el triángulo, y guarde sus datos en PostgreSQL mediante Dapper y Npgsql.

2. Marco teórico

ASP.NET Core y las rutas

ASP.NET Core permite crear aplicaciones que reciben solicitudes web y devuelven respuestas. En una Minimal API se definen rutas con métodos como MapGet y MapPost. En esta práctica, MapGet muestra las pruebas y el formulario, mientras MapPost recibe sus datos. La plantilla inicial se genera con dotnet new web (Microsoft, s. f.).

Clases, objetos y constructores

Una clase describe propiedades y comportamiento. Un objeto es una instancia creada a partir de ella, y el constructor permite asignar su estado inicial (Microsoft, 2025). Punto representa X y Y. Triangulo recibe tres objetos Punto y reúne los lados y el tipo. Se mantuvieron esas clases en lugar de separar los cálculos de la estructura del profesor.

Dapper y Npgsql

Dapper agrega métodos a las conexiones de datos para ejecutar SQL y trabajar con parámetros. Su operación Execute devuelve el número de filas afectadas (DapperLib, s. f.). Npgsql permite que una aplicación .NET abra una conexión con PostgreSQL y ejecute operaciones en ella (Npgsql, s. f.). En el proyecto se usa ExecuteAsync para insertar y NpgsqlConnection para acceder a Neon.

PostgreSQL y restricciones

Las restricciones establecen condiciones que deben cumplir los datos. NOT NULL evita valores nulos; CHECK comprueba una condición, y PRIMARY KEY identifica filas mediante valores únicos y no nulos (PostgreSQL Global Development Group, s. f.). La tabla triangulo utiliza estas condiciones para los lados, el tipo y las seis coordenadas.

Neon y conexión remota

La documentación de Neon explica que la cadena se obtiene mediante Connect e incluye usuario, contraseña, servidor y base de datos (Neon, 2025). En esta práctica se seleccionó neondb y se configuró DefaultConnection. Se consultó esa sección de la guía; no se utilizó FerretDB en el proyecto.

Distancia y clasificación

Para dos puntos, la distancia se calcula como √((x₂ − x₁)² + (y₂ − y₁)²). L1 une P1 con P2; L2 une P2 con P3; L3 une P3 con P1. Tres lados iguales corresponden a un equilátero, dos iguales a un isósceles y tres distintos a un escaleno. El código compara diferencias pequeñas con una tolerancia de 0.000001 multiplicada por el mayor lado. Esto contempla la precisión limitada de los números decimales usados en el cálculo.

Estructura SQL conservada

CREATE TABLE triangulo (
    x1 DOUBLE PRECISION NOT NULL,
    y1 DOUBLE PRECISION NOT NULL,
    x2 DOUBLE PRECISION NOT NULL,
    y2 DOUBLE PRECISION NOT NULL,
    x3 DOUBLE PRECISION NOT NULL,
    y3 DOUBLE PRECISION NOT NULL,
    l1 DOUBLE PRECISION NOT NULL CHECK (l1 > 0),
    l2 DOUBLE PRECISION NOT NULL CHECK (l2 > 0),
    l3 DOUBLE PRECISION NOT NULL CHECK (l3 > 0),
    tipo VARCHAR(10) NOT NULL
        CHECK (tipo IN ('Isósceles', 'Equilátero', 'Escaleno')),
    PRIMARY KEY (x1, y1, x2, y2, x3, y3)
);
